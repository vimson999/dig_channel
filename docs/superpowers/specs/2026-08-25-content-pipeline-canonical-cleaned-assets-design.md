# 内容流水线规范清洗资产设计

**日期：** 2026-08-25  
**状态：** 已实施
**范围：** 知识星球计划任务、侧边栏和手动投递进入内容流水线后的 MP3/PDF 资产，以及消费这些资产的工作台。

## 目标

下载目录只承担上游接收和清洗输入的职责。清洗成功后，系统中的 MP3/PDF 列表、预览、选择和新建后续工作流必须只引用内容流水线保存的清洗产物；用户删除 Downloads 中的原始文件后，已清洗资产仍可继续使用。

原始路径仍保留在数据库中作为审计记录、清洗失败重试线索和来源追踪信息，但不得再作为清洗成功资产的活动文件引用。

## 问题与边界

当前 `ContentPipelineAsset` 只保存 `source_path`。音频工作台、研报转音频工作台，以及部分 PDF 工作台在生成列表或解析资产时直接检查该路径。因此，清洗产物虽然已写入 `runtime/content_pipeline/batches/<task-id>/..._cleaned/`，原件删除后资产会从列表中消失或无法预览。

本设计改变的是**可选择、可预览、可编排的规范文件引用**，不改写以下历史证据：

- `ZsxqAttachment.local_path`：保留其下载审计语义。
- 已经启动或已经完成的业务任务参数和结果快照：不回写历史输入路径，避免破坏已执行任务的可追溯性。
- 清洗器在清洗开始前对原始输入的读取：清洗完成前仍必须保留原件。

没有进入共享内容流水线、且没有可验证清洗产物的旧式历史任务，不再作为“可选择资产”暴露；它们仍保留在历史任务详情中。需要再次使用时应重新投递，而不是引用可能已不存在的下载原件。

## 已选方案与备选方案

采用在现有 `content_pipeline_assets` 上增加规范清洗产物字段的方案。

这是最小且一致的扩展：该表已经按 `media_type + content_sha256` 作为三种上游的共享去重账本，每个规范源文件恰好对应一个当前可用的清洗产物。无需另建第二套资产主表。

未采用的方案：

1. 每个工作台自行从 `PublicationTask.result` 查找 `cleaned_files`。这会复制复杂的路径和兼容逻辑，且任务 JSON 不适合作为长期资产索引。
2. 新建独立产物表。它更适合未来保留多个版本，但当前每个规范输入只需要一个现行清洗产物，会增加关联、迁移和查询复杂度。
3. 保留对 Downloads 原件的静默回退。它会在清洗成功后重新使用未清洗内容，与本设计目标相冲突。

## 数据模型

在 `ContentPipelineAsset` 增加以下可空字段：

| 字段 | 含义 |
| --- | --- |
| `cleaned_path` | 系统管理的清洗产物绝对路径；必须位于内容流水线输出根目录内。 |
| `cleaned_sha256` | 写入该产物时计算的 SHA-256，用于审计和修复校验。 |
| `cleaned_bytes` | 写入时的字节数。 |
| `cleaned_at` | 清洗产物被成功登记的 UTC 时间。 |

`source_path`、`content_sha256` 和 `source_mode` 保持原有语义：它们描述首次接受的原件及其三种上游来源，不会被清洗产物覆盖。

资产状态继续使用现有的 `reserved`、`cleaning`、`cleaned`、`failed` 等值。规范文件可用性由状态和 `cleaned_path` 的实际校验共同决定：

- `ready`：状态为 `cleaned`，文件存在、扩展名匹配且大小大于零。
- `processing`：状态为 `reserved` 或 `cleaning`；不作为可选择文件返回。
- `unavailable`：状态为 `cleaned` 但登记文件缺失、大小异常或位于输出根目录之外；返回明确的修复错误，不回退原件。
- `failed`：清洗失败；不作为可选择文件返回。

## 规范解析层

新增一个内容流水线资产解析服务，作为所有 MP3/PDF 消费端唯一的文件路径入口。它提供三个职责：

1. 根据 `ContentPipelineAsset` 返回已验证的规范清洗文件和可用性原因。
2. 将清洗器的 `cleaned_files` 结果按源路径登记到该任务保留的资产行。
3. 根据 `pipeline:<asset-id>` 或旧的知识星球附件 ID 解析资产。旧附件 ID 仅用于兼容已有页面链接；解析时通过它的原始路径定位对应的规范资产，最终仍返回清洗路径。

解析器不会返回 `source_path` 作为成功后的工作文件。它也不会在清洗完成资产的输出丢失时降级使用原件。

新的列表以 `ContentPipelineAsset` 为主表，只列出 `ready` 资产。若资产的 `source_path` 仍能与 `ZsxqAttachment.local_path` 对应，可附带主题、栏目、下载次数等知识星球展示元数据；这些元数据不是文件可用性的前提。三个上游均使用同一类 `pipeline:<asset-id>` 引用，防止同一内容以“侧边栏项”和“手动项”重复出现。

## 清洗与登记流程

```text
计划任务 / 侧边栏 / 手动目录
            │
            ▼
ContentPipelineAsset（原件指纹、审计来源、reserved）
            │
            ▼
PDF / 音频清洗器写入 runtime/content_pipeline/batches/<task-id>/..._cleaned
            │
            ▼
登记 cleaned_path + cleaned_sha256 + cleaned_bytes + cleaned_at
            │
            ▼
标记 cleaned，自动发布与所有工作台均通过规范解析层读取产物
```

登记顺序必须是：逐一验证并记录清洗输出，再逐资产更新状态。成功登记的资产标记为 `cleaned`；清洗失败、输出缺失或登记失败的资产标记为 `failed`，以便后续重新投递时可被去重闸门安全接管。只有当一个任务没有任何资产成功登记时，整个任务才标记失败并且不触发自动发布。部分成功的任务以完成状态结束，结果中准确保留成功、失败和跳过数量，自动发布只接收已成功登记的产物。

知识星球同步配置的自动视频与 PDF 基础文案物料属于同一条后续链路：同步阶段只记录为 `awaiting_clean`，不得直接读取刚下载的原件投递。每个成功登记的 MP3 才触发视频编排；每个成功登记的 PDF 才触发视频编排和基础文案物料。单个文件的后续投递失败只记录在该文件的旁路结果中，不阻断本批其他已清洗文件的发布或旁路投递。

PDF 清洗器的结果会补充绝对 `source_path` 字段，与音频清洗器已有的字段统一，使登记不依赖文件名猜测或相对目录推断。

清洗任务不得因为 `failed_count > 0` 直接抛出并中止整批；它必须消费每个文件的结果，保留已成功登记的清洗产物，并仅在成功登记数为零时把任务作为整体失败。

## 历史回填与修复

数据库迁移仅负责新增字段，不读取本地文件。新增一个可重复执行的维护命令，用于扫描已有 `content_pdf_clean` 和 `content_audio_clean` 任务的 `cleaned_files`：

1. 只处理具有对应 `ContentPipelineAsset` 的任务。
2. 只登记存在、非空、媒体类型正确且位于内容流水线输出根目录内的文件。
3. 对新格式结果按绝对 `source_path` 精确匹配资产；对旧 PDF 结果仅在任务输入和相对源路径能唯一对应时登记。
4. 无法唯一匹配或产物不存在时不猜测、不覆盖，输出可审计的跳过原因。

部署后先运行一次回填。以后每个清洗任务在完成时自动登记，因此不需要常规人工维护。输出丢失时，资产会在解析时显示不可用，可通过同一维护命令复检；恢复方式是从仍在的清洗输出重新登记，或重新投递原始文件。

实际部署顺序：

```bash
alembic upgrade head
PYTHONPATH=src/backend venv/bin/python scripts/maintenance/backfill_content_pipeline_cleaned_assets.py --dry-run --limit 200
PYTHONPATH=src/backend venv/bin/python scripts/maintenance/backfill_content_pipeline_cleaned_assets.py --limit 200
```

原始下载文件必须保留到清洗任务完成、且对应 `cleaned_path` 经解析器验证为 `ready`。只有完成这个确认后，Downloads 原件才可删除。

## 消费端改造范围

以下用户可见的资产列表、预览与新建任务入口改为只使用规范解析层：

- MP3 视频工作台：`src/backend/services/mp3_video_workflow.py` 及其预览、元数据解析。
- 研报转音频：`src/backend/api/report_audio_workflow.py`。
- 研报基础文案：`src/backend/api/report_script_material_workflow.py`；该接口同时服务基础文案、火柴人视频和视觉方案页面。
- 今日研报严选（Top10）：`src/backend/api/report_top10_workflow.py` 与 `src/backend/services/report_top10_workflow.py`。

工作台保留来源标签，并新增/显示“已清洗”状态；MP3、研报转音频、基础文案、火柴人视频、视觉方案和 Top10 页面上的“已同步 MP3/PDF”文案改为“已清洗 MP3/PDF”。预览和新建工作流接收的 `pipeline:<asset-id>` 引用保持稳定，避免前端依赖本地绝对路径。

自动发布继续直接消费本次清洗任务的输出目录，但使用同一已登记的规范产物集合进行校验。清洗器、下载器和下载历史接口保留对原件的审计引用，不属于可选资产列表。

## 错误处理

- 单个清洗输出缺失或无法登记：仅该资产标记 `failed`，其他成功登记的同批资产仍完成、仍可自动发布；任务结果列出该文件失败原因。
- 清洗任务的所有输出都无法登记：任务失败，不触发自动发布。
- 清洗产物后续被手动删除：列表不返回该项，按 `unavailable` 计数；对直达预览或创建任务请求返回可操作的“清洗产物缺失，请修复或重新投递”错误。
- 已清洗资产绝不退回 `source_path`，即使原件仍在 Downloads。
- 旧附件 ID 在没有匹配规范资产时返回“尚无可用清洗产物”，而非使用原件。
- 自动视频与基础文案旁路在清洗产物未登记或不可用时显示“等待/跳过清洗产物”，不会读取原件，也不会阻断同批其他成功资产。

## 验收标准

1. 手动、侧边栏和计划任务提交的 MP3/PDF，在清洗成功后均能从对应工作台列表中看到；删除原始 Downloads 文件后仍可预览和新建后续任务。
2. 清洗中的、失败的和缺失产物的资产不会误作为可选择文件。
3. 同一内容不会同时以知识星球原件和流水线产物重复出现。
4. MP3 工作台和所有 PDF 工作台（研报转音频、基础文案、火柴人视频、视觉方案、Top10）对 `pipeline:<asset-id>` 的预览与任务创建均使用 `cleaned_path`。
5. 回填命令只登记可验证的现有输出，可重复运行，不会猜测或覆盖错误映射。
6. 原始下载路径和既有历史任务快照保持不变。
7. 自动发布仍能在一批中部分文件失败时发布已成功登记的文件，并在通知中准确反映成功与失败数量。
8. 自动视频和基础文案物料只从已登记的 `cleaned_path` 创建任务；删除原始 Downloads 文件后仍可创建，未清洗或失败的单个文件不会中断同批其他文件。
