# 文案到成片通用工作流设计

## 设计结论

新增一个面向用户文案的通用“文案到成片”工作流。它以一份长文案为输入，依次完成语音生产、视觉分镜编辑、Gemini 浏览器批量生图、整篇音频与分镜时间轴对齐，以及 MP4 渲染。

火柴人、哆啦 A 梦/机器猫及未来风格不是独立工作流；它们是可插拔的视觉方案。视觉方案只定义 Gemini 图片提示词的稳定风格契约、画幅、角色一致性要求和禁止项。所有方案共用同一套任务状态、音频、图片、对齐和渲染能力。

## 已确认的产品原则

1. 用户入口是一个独立的“文案到成片”页面，并从全局菜单进入。
2. 用户首先粘贴整篇文案；不依赖 PDF、Gemini 文案解析或研报任务。
3. 豆包浏览器朗读继续通过现有 `doubao_browser_tts` Celery 队列执行，最终交付完整 WAV。
4. 语音切分与视觉分镜是两个不同概念：语音切分以浏览器可靠性为目的，视觉分镜以画面节奏为目的。
5. 用户在生成图片前可以编辑“分镜文案 ↔ 图片提示词”表格；每行生成一张图片。
6. Gemini 生图继续通过现有真实浏览器与登录 Profile 执行；失败图片可单独重试。
7. 以整篇 WAV 为唯一视频音轨，通过现有 ASR/单调文本匹配能力将分镜映射到时间轴；不为每个镜头重复调用 TTS。
8. 视觉方案只影响图片提示词组合，不改变音频、对齐和视频渲染主流程。
9. 任何阶段都必须持久化，刷新页面、浏览器验证码/登录失效或单张图片失败后均可从失败处续跑。
10. 首版最终音频只提供 WAV；视频交付 MP4。

## 范围

### 本阶段包含

- 一份原始文案的持久化工作流任务；
- 可编辑的语音分段预览，默认按完整句子优先、单段约 800 字；
- 豆包浏览器批量朗读、分段 WAV 复用、失败重试及完整 WAV 合并；
- 可编辑的视觉分镜表，包含序号、覆盖文案、图片提示词、视觉方案和图片状态；
- 视觉分镜与文案的顺序和覆盖完整性校验；
- Gemini 浏览器按分镜批量生成图片；
- 视觉方案提示词契约的组合与版本记录；
- 整篇 WAV 的 ASR 时间轴对齐、字幕与 MP4 渲染；
- 父任务、子任务、验证码/登录阻塞、局部重试和下载接口；
- 独立页面、工作流详情与菜单入口；
- 覆盖核心状态机、接口、提示词组合、时间轴和页面契约的自动化测试。

### 本阶段不包含

- 自动使用大模型替用户撰写图片提示词；页面先根据文案生成可编辑分镜行，图片提示词由用户填写或修改。
- MP3 转码、配乐、转场库、片头/片尾模板、批量发布。
- 替换或迁移既有研报、火柴人和 MP3 视频页面；它们保持兼容。
- 为每一种视觉方案复制任务或渲染代码。

## 领域模型

### 通用父任务

父任务 feature 暂定为 `script_video_workflow`。它保存：

- 原始文案、规范化文案哈希和创建者；
- 语音分段清单及豆包子任务 ID；
- 完整 WAV 元数据；
- 已选视觉方案 key 与提示词 profile 版本；
- 结构化视觉分镜、图片任务状态和图片路径；
- 音频对齐清单、字幕路径、视频路径和有限摘要；
- 当前阶段、等待中的子任务、错误和可恢复状态。

首次实现可复用既有场景资产、音轨和 FFmpeg 渲染基础设施，但新父任务 API、前端语义和状态机必须是通用的，不能暴露“火柴人”作为工作流名称。

### 视觉方案

每个方案是版本化配置，而不是新的工作流代码：

```text
key, name, description,
image_prompt_contract, profile_version,
optional Gemini URL override
```

最终图片请求按以下形式构成：

```text
用户填写的场景提示词
+ 当前分镜的文案上下文
+ 视觉方案内置提示词契约
```

现有 `stick_figure` 和 `doraemon` 方案作为首批选项；之后可通过同一注册机制增加更多方案。

### 语音分段与视觉分镜

语音分段只负责可靠地把大文本提交给豆包；不直接决定换画。

视觉分镜表从原文按较短句群生成初稿。用户可以编辑文案片段、拆分或合并行、填写图片提示词。提交图片生成前必须验证分镜顺序稳定且覆盖全部有效文案；无提示词、空文案或重叠/缺口均应被明确指出。

## 用户工作流

1. 在“文案到成片”页面粘贴长文案，选择视觉方案。
2. 页面显示可编辑的豆包语音分段；用户确认后投递语音任务。
3. 页面显示每段语音状态和整体进度；所有成功片段按原顺序合并为完整 WAV。
4. 页面生成可编辑的视觉分镜表。用户逐行填写或调整图片提示词，然后确认生成图片。
5. 系统向 Gemini 浏览器队列投递图片任务；每张图独立显示状态、预览与重试操作。
6. 所有图片完成后，系统以完整 WAV 和分镜文案生成连续时间轴；对齐失败时不进入渲染。
7. 系统以图片、整篇 WAV、时间轴和可选字幕渲染 MP4。
8. 页面提供 WAV、图片清单、时间轴和 MP4 下载；任意失败阶段可局部续跑。

## 状态机

```text
draft
  → script_ready
  → audio_queued → audio_processing → audio_ready
  → storyboard_ready
  → images_queued → images_processing → images_ready
  → alignment_queued → alignment_ready
  → video_queued → completed
```

任意外部浏览器阶段可以转为 `blocked_by_login` 或 `blocked_by_captcha`，保留当前阶段和子任务引用。用户完成登录/验证后从相应阶段重投；不重复生成已完成的 WAV 或图片。不可恢复错误进入 `failed`，但允许按阶段重新执行。

## 队列与复用边界

- 语音子任务：继续投递 `doubao_browser_tts` 队列。
- Gemini 图片子任务：继续使用既有 Gemini 浏览器/场景图片队列和 profile 管理。
- 对齐与视频渲染：继续使用既有 ASR、时间轴和 FFmpeg 渲染能力。
- 父工作流只编排子任务，不能在 Web 请求中等待浏览器、ASR 或 FFmpeg 完成。

既有火柴人工作流的图片资产、整篇音频对齐和渲染逻辑将被抽取或参数化，使其接受通用父任务和视觉方案。既有 API 和任务名保留兼容入口。

## 页面设计

页面使用分步工作台，而非一次性表单：

1. **文案**：大文本输入、字数统计、视觉方案选择。
2. **语音**：语音分段列表、编辑、提交、单段状态、完整 WAV 播放和下载。
3. **分镜**：表格编辑、文案覆盖校验、视觉方案提示、图片提示词输入。
4. **图片**：批量生成、单图预览、失败重试。
5. **对齐与成片**：时间轴摘要、渲染进度、WAV/MP4 下载。

页面轮询应遵循现有隐藏标签暂停、请求去重和异常退避模式。进入详情页或刷新后，页面仅根据服务端父任务及结构化子资产恢复。

## 错误处理

- 空文案、超出系统限制或拆分结果为空：阻止创建/投递并显示可操作错误。
- 豆包段失败：成功段保留，仅失败段按现有重试策略重投。
- 豆包登录/验证码：进入明确阻塞态，提供 profile、截图和恢复操作。
- 分镜覆盖校验失败：禁止图片生成和对齐，标出有问题的行。
- Gemini 单图失败：不破坏已完成图片；允许单行重试。
- Gemini 登录/额度阻塞：保留成功图和未完成图，通知并允许续跑。
- 音频/分镜一致性或 ASR 置信度不足：明确失败，不产生可能错位的视频。
- FFmpeg 失败：保留完成的音频、图片和时间轴，允许仅重试渲染。

## 验收标准

1. 用户可从菜单进入页面，输入长文案并看到独立工作流任务。
2. 文案可在投递前按句子优先拆分并编辑；语音阶段按顺序合并为可下载 WAV。
3. 用户可编辑每个视觉分镜与图片提示词，且系统阻止不完整的覆盖表。
4. 选择火柴人或哆啦 A 梦等方案时，只有 Gemini 图片提示词契约不同，其他工作流阶段一致。
5. 每张图片均通过现有真实 Gemini 浏览器能力生成、显示状态并支持局部重试。
6. 成片使用完整 WAV 一次作为音轨，图片显示时长与对齐时间轴连续覆盖整篇音频。
7. 任何外部浏览器、对齐或渲染失败均有明确状态，不会误报成功，并能从完成产物继续。
8. 既有研报、火柴人和 MP3 视频工作流的相关测试继续通过。

## 实施约束

- 保持当前工作树中用户的未提交改动不变；本功能只触及新增文件和必要的共享注册点。
- 先为每个新增行为写失败测试，再写最小实现。
- 不在 Web 请求线程内执行真实浏览器、长时间轮询、ASR 或 FFmpeg。
- 不因新增视觉方案复制豆包、Gemini、对齐或视频渲染业务代码。
