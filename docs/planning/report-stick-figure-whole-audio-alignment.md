# 火柴人视频整篇音频复用与时间轴对齐设计

## 目标

同一份研报已经在“研报转语音”生成完整 WAV 时，火柴人视频编排不得重复生成逐镜头 TTS。系统应复用完整 WAV，将 001 开始的正文分镜映射到音频时间轴，并与分镜图片合成视频。

同时保留原有逐镜头 TTS，形成两种音频策略：

- `whole_audio`：复用整篇 WAV，通过 ASR 时间戳和原文单调对齐生成分镜时间轴。
- `scene_tts`：逐镜头生成 WAV，每张图片时长直接取对应 WAV 时长。
- `auto`：优先选择通过完整性校验的 `whole_audio`，否则选择 `scene_tts`。

## 成功经验复用

- 参考 `report_audio_workflow`：复用结构化 WAV 路径、时长、PDF 附件 ID 和基础文案。
- 参考 `asr_cache_service.transcribe_with_cache`：复用本地 ASR 缓存、词段时间戳和模型管理。
- 参考 `report_stick_figure_video`：复用 000 排除、FFmpeg 渲染、字幕、水印、倍速和原子文件落盘。
- 参考 `report_stick_figure_scene_assets`：时间轴落结构化行，不把逐镜头列表写入 `publication_tasks.result`。
- 参考 `runtime_guard`：任务入队受数据库压力和并发准入保护。
- 参考现有视频任务：父子任务状态、失败终态、失败续跑、产物完整性校验。

## 数据契约

### `report_stick_figure_audio_tracks`

每个火柴人工作流只保留一个当前整篇音轨绑定：

- 工作流、分镜、来源研报语音任务 ID。
- WAV 路径、字节数、时长。
- 来源文案哈希、分镜正文哈希。
- 对齐状态、场景数、平均/最低置信度、ASR 缓存键。
- 错误原因和时间戳。

### `report_stick_figure_scene_assets`

增加每个镜头的结构化时间轴字段：

- `timeline_start_seconds`
- `timeline_end_seconds`
- `timeline_confidence`
- `timeline_source`

完整对齐明细保存到工作流目录下的 `audio_alignment.json`；任务表只保存清单路径和有限摘要。

## 对齐算法

1. 校验完整 WAV 存在且时长有效。
2. 校验音频来源文案与 001 起全部分镜正文为同一内容，避免错误复用同名 PDF 的旧音频。
3. 对 WAV 运行带缓存的 ASR，获得带开始/结束时间的短文本段。
4. 对来源文案、分镜文案和 ASR 文本做一致的字符归一化。
5. 使用单调序列匹配，将分镜原文字符区间映射到 ASR 字符时间轴。
6. 相邻镜头使用匹配锚点中点建立连续边界；缺失锚点按正文字符位置插值。
7. 第一镜头从 0 秒开始，最后镜头覆盖完整音频尾部；时间轴不得有空洞、重叠或倒序。
8. 来源文案一致度或 ASR 对齐置信度低于阈值时明确失败，不静默产出错位视频。

## 视频合成

- `scene_tts`：保持现有逐镜头图片/WAV 交错输入和 concat。
- `whole_audio`：图片按时间轴持续时间 concat，完整 WAV 只作为一个连续音频输入；倍速同时作用于图片时长和完整音轨。
- 两种模式共用字幕、水印、输出路径、进度和失败续跑。

## 研报转语音页面

原横屏“研报截图”方案保持不变；新增“火柴人分镜”方案入口。入口创建火柴人工作流时直接引用当前研报语音任务，复用基础文案和完整 WAV，只生成分镜、图片及对齐时间轴。

## 验收

- 已有整篇 WAV 时，点击音频准备不会创建豆包分段 TTS 子任务。
- 无整篇 WAV 或用户明确选择时，仍可逐镜头生成 TTS。
- `whole_audio` 时间轴连续覆盖完整 WAV，001 为首个正文画面，000 不进入正片。
- 合成视频时音频只输入一次，成片时长与倍速后的完整 WAV 一致。
- 列表和轮询不读取大 JSON；时间轴逐镜头字段来自结构化表。
- ASR、对齐、渲染任一失败均进入明确终态，并可失败续跑。
