# 2026-07-29 研报关键帧任务被误标为视频生成完成

## 基本信息

- 状态：已修复
- 严重级别：P2
- 影响模块：研报转语音详情页 / 任务流程状态
- 首次发现：2026-07-29
- 修复提交：待提交
- 根因分类：前端状态语义未按生成模式分支
- 复发键：REPORT-AUDIO-OUTPUT-MODE-DISPLAY
- 是否复发：首次
- 关联记录：无
- 防线层级：contract_test

## 现象

只选择“关键帧 + 封皮”的任务完成后，详情页第五个流程节点仍显示“视频生成 / 已完成”，顶部摘要还显示“竖屏 scheme3”，使用户误以为已经生成竖屏 MP4。

## 影响

任务和资产本身正确，但页面把图片产物描述成视频产物，导致用户无法从任务概览判断本次到底生成了关键帧还是完整视频。

## 根因

流程节点使用固定的“视频生成”标签，顶部摘要也直接读取 `vertical_video_scheme`。两处都没有先判断 `video.render_mode=keyframes`，而关键帧模式同样会保存竖版背景方案，因此被错误解释为竖屏成片。

## 解决思路

以 API 已公开的 `video.render_mode` 为主、`video.status=keyframes_ready` 为兼容回退，统一解析任务输出模式。流程节点和顶部摘要共享该判断，不改变任务状态或后端产物。

## 实际方案

- 关键帧模式第五节点显示“关键帧/封皮”，完整视频模式继续显示“视频生成”。
- 关键帧摘要显示实际图片数量，并将方案描述为“方案三竖版关键帧”。
- 完整视频摘要才使用“完整视频”和竖屏方案描述。
- 更新前端缓存版本并增加静态契约测试。

## 验证

- 运行前端 JavaScript 语法检查。

## 复发预防

详情页以后新增输出模式时，必须由统一的输出模式解析函数驱动流程节点和摘要，禁止直接把方案字段等同于实际成片。
