# 整篇 WAV 就绪后试听区仍显示无音频

## 基本信息

- 状态：已修复并完成真实页面音频加载验收
- 严重级别：中
- 影响模块：火柴人视觉视频 / 视频合成 / 音频方案切换 / 倍速试听
- 首次发现：2026-07-24
- 修复提交：待提交
- 根因分类：前端派生状态未随数据源切换重建
- 复发键：`AUDIO-PREVIEW-DERIVED-STATE`
- 是否复发：首次
- 关联记录：`2026-07-24-visual-detail-report-audio-source-misrouted.md`
- 防线层级：local_patch / contract_test / observability

## 现象

视频合成区域的“音频方案”已经可以选择并选中了“复用整篇 WAV”，逐镜头区域也已显示完整 WAV
时间轴，但“倍速试听”仍显示“首段分镜 TTS”和“当前音频方案还没有可试听音轨”。

## 影响

整篇 WAV 实际存在且可以用于视频合成，但用户无法在合成前试听或验证倍速，页面的两个区域对同一音频状态给出互相矛盾的结论。

## 根因

试听增强面板只在首次渲染时决定生成 `<audio>` 播放器还是“无音频”占位块。
后续整篇 WAV 对齐完成，或用户从尚无分段 TTS 的模式切换为“复用整篇 WAV”时，
`syncAudioPreview()` 只尝试更新已经存在的 `<audio>`。如果首次渲染的是占位块，函数会因为找不到播放器直接返回，
既不会创建播放器，也不会更新“首段分镜 TTS”的来源标签。

这是典型的派生 UI 状态失联：下拉框取最新状态，试听区仍保留首次渲染快照。

## 解决思路

把试听内容区提升为可替换的稳定容器。每次音频方案或倍速变化时，重新计算当前来源：

- 新来源存在但播放器不存在时，将占位块替换为播放器；
- 新来源不存在但播放器存在时，恢复占位块；
- 两边都有来源时更新 URL、重新加载并应用倍速；
- 同步更新试听来源标签。

## 实际方案

- 新增 `audioPreviewSourceType()`，集中计算“整篇 WAV / 首段分镜 TTS”标签。
- 新增 `audioPreviewMarkup()`，统一生成播放器或空状态。
- 为试听内容增加 `data-audio-preview-box` 稳定容器。
- 扩展 `syncAudioPreview()`，覆盖无音频→有音频、有音频→无音频以及音源 URL 变化三种状态迁移。
- 更新详情页脚本版本，避免浏览器继续使用旧静态资源。

## 复发预防

1. 由异步任务改变的数据不能只更新控制项，所有派生区域必须覆盖空→有、有→空和来源切换。
2. 媒体组件的回归检查必须同时验证选择值、来源标签、播放器节点和媒体加载状态。
3. 占位 UI 不能成为一次性结构；数据可能异步就绪时必须提供稳定容器或完整重渲染路径。
