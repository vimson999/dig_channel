# 研报音频后台标签页轮询放大为 HTTP/SQL N+1

## 基本信息

- 状态：代码与回归完成，待下一完整日志窗口验收
- 严重级别：P1
- 影响模块：研报音频列表与详情页 / publication_tasks / PgBouncer / PostgreSQL
- 首次发现：2026-08-05
- 修复提交：当前工作区
- 根因分类：高频状态轮询、隐藏标签页未停轮询、批量摘要后重复逐项读取
- 复发键：`HOT-PATH-PAYLOAD-POLLING`
- 是否复发：是；此前已要求单飞轮询、批量摘要和热点接口往返预算，但研报音频列表仍在每轮先逐项查状态再批量刷新
- 关联记录：`2026-07-10-report-audio-projection-and-parent-roundtrips.md`、`2026-07-22-terminal-polling-image-repair-payload-recurrence.md`、`2026-07-22-pgbouncer-cold-pool-connect-timeout.md`
- 防线层级：local_patch / contract_test / observability

## 现象

- 2026-08-04 06:02:19 至 2026-08-05 06:02:19，`GET /api/report-audio-workflows/jobs/:id/status` 1,150 次，累计 1,927.298 秒，P50/P95/最大 0.622/4.987/61.635 秒。
- 同窗口列表接口 381 次、累计 459.254 秒。前端 `refreshJobs()` 对活动任务逐项 `refreshJob()` 后，又立即调用 `loadHistory()`；一个页面轮询周期会形成 N 个状态请求加 1 个列表请求。
- 列表接口已经通过 `_query_jobs_page()` 和 `_child_summaries_for_parent_ids()` 批量返回当前页父任务投影及子任务摘要，逐项状态请求的结果随后会被列表结果覆盖。
- 页面隐藏后仍保留定时器；长时间打开的后台标签页会继续制造连接与查询压力。

## 影响

- 状态端点成为全站累计耗时最高端点，占本轮完整 HTTP 累计耗时约 30.6%。
- PgBouncer/公网链路抖动时，每个页面周期中的并发逐项请求会同时放大连接等待、60 秒 server-closed 长尾和用户可见超时。
- PostgreSQL 实时 EXPLAIN 为毫秒级，继续增加索引无法消除这类往返放大。

## 根因

前端把“单个新任务的即时确认”与“历史列表的周期刷新”复用了同一逐项状态读取逻辑，忽略了列表接口已经提供批量摘要；同时没有使用 Page Visibility API 暂停后台标签页轮询。单飞门禁只能避免同一页面的轮询重叠，不能消除每轮内部的 N+1。

## 解决思路

- 周期轮询只调用一次批量列表接口；保留任务刚提交后的单任务即时确认。
- 页面隐藏时停掉列表和详情定时器，重新可见后恢复。
- 提高默认轮询间隔并设置安全下限，降低远端链路抖动时的并发放大。

## 实际方案

- `refreshJobs()` 删除活动任务逐项 `Promise.all(refreshJob)`，统一使用批量 `loadHistory()`。
- 列表页默认轮询从 8 秒调为 15 秒、最小值从 1 秒调为 5 秒；详情页从 6 秒调为 10 秒。
- 列表页和详情页监听 `visibilitychange`；隐藏时清理定时器，可见时恢复受控轮询。
- 更新前端 cache-bust，并增加结构契约测试，锁定批量轮询与隐藏标签页暂停行为。

## 验证

- 定向前端、DB 投影与日志分析器测试通过，完整结果记录在 2026-08-05 DB 巡检报告。
- 没有修改业务字段、删除原始 JSON、执行 DDL、回填数据或变更生产配置。
- 静态资源按请求读取，本次不需要重启后端、Celery 或 scheduler；用户刷新页面即可加载新 cache-bust 版本。

## 复发预防

- 列表页周期刷新必须优先使用单个批量端点；禁止在同一周期内先逐项读取再批量覆盖。
- 所有持续轮询页面必须具备 single-flight、Page Visibility 暂停、终态停止和合理最小周期四项契约。
- DB 巡检按端点累计耗时与请求量持续验收；下一完整窗口预期研报音频状态请求数与列表请求数之比显著低于本轮 3.02。

## 后续事项

- 下一轮分别统计列表页与详情页状态流量；若状态端点仍高频，继续定位同时打开的详情页数量，而不是回退到增加索引。
- 逐步把同样的 Page Visibility 契约推广到日志中有实际高累计耗时证据的其他轮询页面。
