# B站自动投稿后仍需手工调整双比例封皮

- 首次发现：2026-07-24

- 复发键：`ASSET-PROJECTION-CONSISTENCY`

## 现象

自动化已成功向 B站投递横屏视频和白板火柴人视觉方案视频，但投稿后台的 4:3、16:9 封皮预览需要人工重新移动裁切框，
否则标题前缀或副标题可能被切掉。

## 影响

每次自动投稿后仍要进入 B站创作中心逐条修封皮，自动投递没有形成真正无人值守的闭环。
同一任务投递多个视频版本时，重复操作成本进一步放大。

## 根因

只读检查两条真实上传记录确认：

- 视觉方案视频绑定了专用 `bilibili_cover`；
- 横屏视频仍绑定普通 `cover`。

普通横屏封面是 16:9 构图，没有为 B站的 4:3 展示保留左右安全区。专用 B站封皮虽然是
1146×717，但文字左边距只有 64 像素；B站将同一封皮居中裁成 4:3 时会切掉约 95 像素左右边缘，
因此专用封皮本身也不能保证双比例安全。

项目此前只完成了“生成并上传一张 B站封皮”，没有把“同一张图同时适配 4:3 与 16:9”纳入资产合同。

## 解决思路

B站上传接口只需要一张封皮，由平台派生不同展示比例。与其在投稿后自动操作裁切 UI，
更稳定的方案是生成一张双比例安全母版：背景允许被裁切，所有文字和标识必须位于居中的
4:3 与 16:9 公共安全矩形内。

同时所有 B站视频变体都默认使用这张专用封皮，不再让横屏视频回退到普通 16:9 封面。

## 实际方案

- 前端 B站封面选项统一把“B站双比例安全封皮”排在第一位，覆盖横屏、竖屏和视觉方案视频。
- 后端未显式指定 `cover_key` 时，所有视频变体统一优先解析 `bilibili_cover`。
- 1146×717 封皮的关键文字左/右边距从 64 增加到 150 像素。
- 标题区整体上移并收紧字号，副标题和可选底款保持在 16:9 的上下安全区内。
- 更新详情页与封面工具台静态资源版本。

## 验证

- 真实上传投影确认：视觉方案记录原为 `bilibili_cover`，横屏记录原为 `cover`，与问题表现一致。
- 实际渲染 1146×717 新封皮，并分别执行居中 4:3（956×717）和 16:9（1146×645）裁切。
- 两种裁切结果的机构标签、两行标题和副标题均完整保留，4:3 左侧仍有约 55 像素可见留白。
- `test_report_audio_workflow_api` 49 条测试通过。
- 前端两个 JavaScript 文件语法检查和 `git diff --check` 通过。

## 复发预防

1. 平台专用视觉资产的合同必须包含展示裁切规则，不能只验证源文件尺寸。
2. 自动投稿默认封面必须由前后端共享同一优先级，不能只改页面下拉顺序。
3. B站封皮验收固定包含 1146×717 母版、居中 4:3 和居中 16:9 三张预览。
4. 新增视频变体时必须显式证明其默认 `cover_key` 仍为 `bilibili_cover`。
