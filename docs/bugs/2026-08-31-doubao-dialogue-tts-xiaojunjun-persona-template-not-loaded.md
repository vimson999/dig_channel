# Doubao 对话 TTS 未持久加载“小君君”栏目人设

## 基本信息

- 状态：RESOLVED
- 严重级别：P2
- 影响模块：`doubao-dialogue-tts` 栏目模板、审阅稿生成、主持人口播清单
- 首次发现：2026-08-31，洪灏《市场将如何定价沃什和贝森特的巅峰对决》审阅稿
- 当前处置：已新增项目默认选择器、结构化小君君 Profile、Skill 路由与 dry-run 门禁，并同步到正式安装目录

## 现象

同一长期运营频道的固定主持人“小君君”在先前成片中已经正常出现，当前稿却被改成无频道身份的通用主持人口吻。用户本应只提交研报或初步解析稿，而不必每次重申栏目人设和固定开场。

## 影响

- 成片失去跨期一致的频道识别度，影响系列内容的听感和品牌连续性。
- 主持人段落容易退化为匿名说明文，即使原文保护仍然正确，节目也不符合栏目定位。
- 用户必须人工发现并纠正，增加审核轮次；若直接合成，会产生不符合频道风格的付费音频。

## 根因

项目设计已明确“小君君”为固定主持人，且规定用户默认不应重复提交人物与栏目提示词；历史 artifact 也保存了完整开场和栏目式点评。

但实际启用的 `doubao-dialogue-tts` Skill 目录只包含 `SKILL.md`、脚本和 manifest schema，没有可加载的栏目模板或项目级人设配置。于是本次生成仅依赖当前输入；编辑时又将初稿中明确标为“特定开场白”的“小君君”误判为可删除的人设包装，造成了漏载。

## 当前缓解

- 本期 manifest 的 `editorial.channel_persona` 明确写入名称、固定开场、表达原则和 `do_not_remove: true`。
- 本期所有主持人口播已按“小君君”口吻重写；洪灏原文保持逐字不变。
- 合成前的审阅稿与 manifest 已同步，且 dry run 通过。

该缓解仅覆盖当前 artifact，不是跨研报的自动加载方案。

## 延后升级方案

在后续集中升级 Skill 时实现项目级、可选择的栏目 profile：

1. 将“小君君”定义为项目/频道 profile，而非硬编码进通用 Skill。
2. 每次开始编辑前解析 profile，并在审阅稿、manifest 元数据和质量门禁中显式记录已加载的 profile。
3. 当用户只提交研报时，自动应用固定开场、主持人语言原则和收束规则；只有用户明确要求时才允许覆盖或停用。
4. 为“只给研报也保留小君君”添加回归测试，并保留“研报作者观点优先、主持人不抢作者身份”的约束。
5. 在付费合成前的审阅界面显示已生效的人设/profile，避免隐式丢失。

## 验收标准

- 新研报在未重复提供人设提示词时，仍生成固定“小君君”开场与一致的主持人口吻。
- 通用 `doubao-dialogue-tts` 不会把“小君君”错误应用到其他频道；profile 必须可选择、可覆盖。
- 原文逐字保护、角色声线、manifest/script 一致性和 dry run 均继续通过。
- 明确将“小君君”视为内容身份而非可删除的运营标签或生产说明。

## 解决结果

- 2026-08-31 在项目根目录新增 `.doubao-dialogue-tts.json`，默认选择 `xiaojunjun-honghao`，其他项目继续使用通用模式。
- Profile 固化固定开场、作者称呼、受众关系、解读契约、禁用后台话术、结尾规则和双声线参数。
- dry-run 会显示 Profile 选择来源、voice ID、最终语速及参数来源；错误开场会在付费合成前失败。
- 旧版基线复现了匿名频道、直呼作者和清澈 `1.00` 三类问题；新版相同场景复测全部符合预期。
- 本地回归测试 `8 passed`，staging 与安装版均通过 `quick_validate.py`，整个升级未调用付费 TTS API。
- 关联备案：`docs/bugs/2026-08-31-doubao-dialogue-tts-host-commentary-audience-alignment.md`。

## 声线速度复审

- “清澈”声线默认 `1.00` 偏慢，但 `1.20` 在完整节目中又显得过快。
- 本期最终确认值为 `1.08`，即 `1.20` 的 0.9 倍；刘飞原文继续保持 `1.00`。
- 后续升级频道 profile 时，将小君君“清澈”语速 `1.08` 作为已验证的默认候选，并保留逐期覆盖能力。
