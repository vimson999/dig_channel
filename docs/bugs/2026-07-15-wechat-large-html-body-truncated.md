# 微信大页面正文被提前截断（2026-07-15）

- 首次发现：2026-07-15

- 复发键：`EXTERNAL-HTML-PREPARSE-TRUNCATION`
- 是否复发：首次
- 关联记录：无

## 现象

关联内容中心抓取微信公众号文章时返回“没有抽取到正文”，但原页面 HTTP 200 且浏览器可正常看到文章。

## 影响

- 正常存在的微信文章被误报为删除或需要验证。
- 批量补抓会把同类大页面全部标记为失败，详情页无法展示正文。
- HTTP 状态和用户提示不一致，容易把结构问题误判为平台风控。

## 根因

抓取器在解析 DOM 前先把 HTML 截到 350,000 字符。微信文章会在正文前输出大量样式和脚本，真实 `#js_content` 可能位于 500,000 字符之后，因此解析器根本看不到正文。

代码层根因是把“持久化正文长度预算”错误复用成“HTML 解析输入预算”；架构层根因是没有用正文节点位置靠后的真实页面作为解析契约。

## 解决思路

保留正文保存上限，但不在 DOM 解析前破坏文档结构。解析器读取完整响应，只收集 `#js_content` 内的可读文本，最终再裁剪输出。这不会把脚本或样式写入数据库，也不会扩大持久化载荷。

## 修复

- 微信 HTML 使用完整响应做流式解析。
- `MAX_FETCH_CHARS` 只限制解析后保存的可读正文，不再限制 DOM 输入。
- 正文捕获使用标签栈；自闭合图片等 void 标签不会错误减少正文容器深度。
- 新增回归测试，覆盖正文节点位于 350,000 字符之后的页面。

## 验证

- 真实 URL 确认：HTTP 200，`#js_content` 位于约第 504,817 字符。
- `venv/bin/python -m unittest discover -s tests/unit -p 'test_external_document_service.py' -v`：12 项通过。
- 新测试构造 350,000 字符以上的前置内容，确认仍能提取后部正文和标题。

## 验证准则

- 同一 URL 抽取到非空正文、标题及作者（页面提供时）。
- 超大页面不会因正文位置靠后而误报删除/验证。
- 保存的正文仍受长度上限约束。

## 复发预防

- 外部 HTML 的输入预算和抽取结果预算必须分开设置。
- 解析器契约必须覆盖正文节点靠后、前置脚本/样式很大的页面。
- 若后续需要限制内存，应使用真正的流式 token 解析并在正文节点结束后停止，而不能对原 HTML 机械截断。
