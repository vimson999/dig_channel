## 现象

用户同时选择横屏成片和方案三竖屏。页面提示方案三没有同一 PDF 且正文图片完整的视觉方案，横屏成片也没有创建任务。

## 影响

- 已具备音频和横屏关键帧的独立输出被方案三前置条件连带阻断。
- 页面只显示竖屏提交失败，无法表达横屏本应可以成功。
- 用户无法区分“方案三尚无视觉工作流”和“横屏合成失败”。

## 根因

前端将所有最终成片选项合并为一次请求。后端在创建 Publisher 子任务之前先校验方案三视觉工作流；校验失败直接返回 400，导致横屏和其他可用竖屏方案均未入队。

## 解决思路

把组合请求视为多个可独立降级的输出：

- 若只请求方案三，前置条件不满足时仍返回失败。
- 若同时请求横屏或其他可用方案，跳过未就绪的方案三，继续创建其余输出任务。
- 响应明确标识部分成功、已提交和跳过的输出。

## 实际方案

- 保留原始请求方案列表，方案三校验失败时仅从可提交列表中移除方案三。
- 横屏存在时继续创建 Publisher 子任务。
- API 返回 `partial_success`、`skipped_outputs`、请求方案和实际提交方案。
- 为“横屏 + 未就绪方案三”补充接口级回归测试。
- 现场任务补投横屏，并创建复用完整文案和 WAV 的白板火柴人视觉工作流。

## 复发预防

- 多输出请求的某个可选输出前置失败，不得阻断无依赖的其他输出。
- API 必须表达全成功、部分成功和全失败，不能用单一错误覆盖多个输出事实。
- 测试必须覆盖组合选择中一个输出未就绪、其余输出正常入队的场景。
