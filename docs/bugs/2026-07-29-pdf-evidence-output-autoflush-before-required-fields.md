## 现象

当天新建的研报转语音任务完成后，详情页却显示“这是旧任务，尚无 PDF 证据映射”。任务日志出现 `final_script_hash` 非空约束失败，但主任务仍正常完成。

## 影响

- Gemini 已返回的证据候选和本地验证文件没有写入结构化证据表。
- 当天新任务被前端错误归类为旧任务。
- 视觉分镜无法读取证据记录，虽然 TTS、音频和其他任务产物未受污染。
- 证据是影子能力，失败只写日志，页面无法区分“旧任务”和“生成后保存失败”。

## 根因

新建 `ReportPdfEvidenceOutput` 后立即加入 SQLAlchemy Session，但必填的脚本哈希、原始响应哈希和解析器版本尚未赋值。随后为选择清洗后 PDF 而执行数据库查询，查询触发 ORM autoflush，PostgreSQL 尝试插入不完整记录并触发非空约束错误。

单元测试使用 SQLite 且未覆盖“非空附件 ID → 查询清洗工作流”的生产路径，因此没有复现该自动 flush。

## 解决思路

- 新对象所有必填字段完整赋值后才加入 Session。
- 清洗 PDF 解析查询放在显式 `no_autoflush` 边界内。
- 证据任务成功或失败都向父任务写入轻量状态摘要，不写入大证据 JSON。
- API 和前端区分旧任务、生成失败和“文件已生成但数据库保存失败”。
- 对已有原始响应和验证文件只补写证据表，不重跑 Gemini、TTS 或视频。

## 实际方案

- 调整 `build_and_store_evidence` 的对象入 Session 顺序。
- 新增真实查询触发场景的回归测试，断言清洗 PDF 查询时 Session 中不存在不完整证据对象。
- 两个证据调用入口在异常后先 rollback，再持久化有界失败摘要。
- API 检测孤立证据 artifact，前端显示可恢复故障而不是“旧任务”。
- 为任务 `6cd25929-eaa4-4742-962a-9c8ecc82fae5` 补写 1 条证据输出和 6 条主张记录。

## 验证

- 64 项相关单元测试通过。
- Python 编译和前端 JavaScript 语法检查通过。
- 真实 PostgreSQL 补写成功：证据输出状态 `partial`，6 条主张、1 条完全验证，清洗后 PDF 被选为截图源。
- 研报转语音与基础文案 Worker 已在空闲状态下重启，后端健康检查通过。

## 复发预防

- 任何带必填字段的新 ORM 对象，在可能触发查询前不得加入 Session。
- 同一事务中的辅助查询必须明确是否允许 autoflush。
- 非阻断能力也必须持久化轻量成功/失败状态，前端不得用“没有结果行”推断任务年代。
- 测试必须覆盖生产数据库特有的查询分支，不能只覆盖无附件的 SQLite 快捷路径。
