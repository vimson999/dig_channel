# 整篇音频对齐完成后被 Web 状态缓存隐藏

## 基本信息

- 状态：已修复并完成真实横屏、方案三成片验收
- 严重级别：P1
- 影响模块：视觉视频详情 / 整篇 WAV 对齐 / 横屏合成 / 方案三竖屏
- 首次发现：2026-07-28
- 修复提交：待提交
- 根因分类：跨进程持久状态 / Web 内存缓存 / 默认值污染
- 复发键：STICK-AUDIO-DURABLE-STATE-OVERLAY
- 是否复发：首次
- 关联记录：2026-07-24-whole-audio-preview-placeholder-stale.md
- 防线层级：shared_guardrail / contract_test / runtime_acceptance

## 现象

Celery 已完成整篇 WAV 转写和 36 个分镜时间轴对齐，数据库音轨状态为 completed，
但详情页持续显示 pending，横屏合成按钮保持禁用。缓存过期后按钮虽可用，
首次合成又错误选择了未生成的逐镜头 TTS，并提示“第 1 段语音尚未完成”。

## 影响

音频、图片和时间轴均已就绪仍无法从页面生成横屏成片；自动或人工验收会把已完成任务误判为卡死。

## 根因

分镜状态包在 Web 进程内空闲缓存 300 秒，而音频对齐由 Celery 进程完成，无法清除另一进程的内存缓存。
接口只对视频渲染状态做了持久状态覆盖，没有对音轨状态做相同处理。
此外，在尚无历史视频任务时，视频状态载荷硬编码 `scene_tts`，覆盖了前端“整篇 WAV 已就绪时优先选择”的逻辑。

## 解决思路

缓存保留用于降低数据库压力，但跨进程 worker 拥有的最终状态必须由窄持久化查询覆盖；
不存在视频任务时不注入虚假的音频方案默认值。

## 实际方案

- 状态轮询和旧版完整素材包都以数据库音轨记录覆盖缓存中的 `audio_strategy`。
- 使用覆盖后的音轨状态重新计算 `audio_ready`、`whole_audio_ready` 和对齐镜头数。
- 没有视频任务时 `video.audio_mode` 返回空值，由前端按实际就绪状态选择整篇 WAV。

## 验证

- API 立即返回 `completed / ready=true / aligned_scenes=36`，不再等待 300 秒缓存。
- 页面默认选择“复用整篇 WAV”，横屏合成正常投递。
- 真实横屏成片 1280×720、148.511 秒；方案三竖屏 1080×1920、148.467 秒。
- 两条成片均复用同一份整篇音轨与 36 段时间轴。

## 复发预防

1. 任何由独立 worker 完成的状态都不能只依赖 Web 进程内缓存失效。
2. 状态接口应对 worker 所有权字段做窄持久化覆盖，避免为刷新整个大载荷放弃缓存。
3. “没有任务”不得伪装成具体方案默认值；默认选择必须由真实可用能力决定。

## 后续事项

- 为更多跨进程媒体状态逐项审查是否已有持久状态覆盖。
