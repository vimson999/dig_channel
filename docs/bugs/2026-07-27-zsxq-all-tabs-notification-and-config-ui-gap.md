## 现象

洪灝和生财有术使用独立的全部 Tab 轻量同步计划。任务提交、完成时没有像前沿信息工作流一样发送节点邮件，只有部分异常能落入外围失败告警。两条计划虽然已经保存在 `system_configs`，但系统同步页面没有读取、展示或保存这些配置，用户只能从代码和数据库中判断计划状态。

## 影响

- 正常提交和完成没有邮件，无法确认计划是否真正推进。
- 凭据或菜单预检失败与 worker 最终失败的通知口径不一致。
- 启停、间隔、抓取页数、凭据和邮件开关无法在页面管理。
- 后端已有配置 API 但没有操作入口，形成“配置存在但不可见”的运维盲区。

## 根因

洪灝/生财计划直接创建 `ZsxqSyncRun` 并投递 `zsxq_sync`，没有创建前沿信息父工作流，因此不会自然经过父工作流的 started/completed/failed 通知节点。首版只复用了同步执行函数和数据库配置，没有同时复用成熟工作流的通知与配置可见性合同。后端 GET/PUT 配置接口已存在，前端却没有调用和渲染。

## 解决思路

保留轻量同步拓扑，不为了发邮件伪造重量级父工作流；在计划投递入口和同步任务终态建立明确的通知适配层，统一复用 `workflow_notification_service`。同时把现有数据库配置 API 接入系统同步页面，并提供单计划立即执行入口。

## 实际方案

- 两条默认计划增加 `notify_milestones`，并持久化到 `system_configs`。
- 菜单/凭据预检失败发送 `sync_failed`；成功入队发送 `workflow_started`。
- `zsxq_sync` 任务最终完成发送 `sync_completed`，重试耗尽后发送 `sync_failed`；中间重试不误发最终失败。
- `sync_completed` 纳入 summary 终态，`sync_failed` 同时纳入 summary 与 failure-only 终态。
- 系统同步页面新增洪灝/生财配置卡，支持启停、间隔、主题数、页数、凭据、节点邮件、翻页停止策略、保存与单独立即执行。
- 保存仍写入原有 `system_configs`，调度器按既有签名热加载，不新增第二份配置源。
