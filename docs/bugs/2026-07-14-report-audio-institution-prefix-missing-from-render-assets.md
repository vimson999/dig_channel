# 2026-07-14 研报视频视觉产物缺少机构前缀

## 基本信息

- 状态：已修复
- 严重级别：P1
- 影响模块：report audio / publisher / 竖屏视频 / 封皮生成
- 首次发现：2026-07-14
- 修复提交：待提交
- 根因分类：视觉资产生成参数合同分叉
- 复发键：`ASSET-PROJECTION-CONSISTENCY`
- 是否复发：是
- 防线层级：shared_guardrail / contract_test

## 现象

- 详情页封皮编辑框已经显示“机构：标题”，但初次生成的 B 站封皮没有机构前缀。
- 同一任务的竖屏视频背景、竖版封皮和播客封皮也缺少机构前缀。
- 单独重新生成 B 站封皮后，磁盘新文件正确，但旧竖屏视频与其他初始产物仍错误。
- `Jefferies / 杰富瑞` 未进入公共机构别名表，文件名和正文已经明确机构时仍错误回退为“机构”。
- `Bernstein / 伯恩斯坦` 虽存在于基础别名表，却未进入封皮工具台映射；Gemini 旧结果中的“盛博”又遮蔽了可靠的 PDF 文件名。

## 影响

- 同一任务的编辑数据、图片和视频出现不同标题。
- 机构信息无法成为稳定的视觉识别信号，且用户需要逐张手工补生。

## 根因

关键帧生成和封皮重生成接口都调用了机构标题标准化函数，但完整视频链路在创建 publisher 子任务时直接传递原始 `main_title`。`institution` 虽作为独立字段传给模板，模板只用它绘制英文眉题，不会自动拼接中文主标题。

结果是同一业务规则分散在三个入口，只有完整视频入口漏掉，造成初次产物与后续编辑、重生成产物不一致。

## 修复

- 在 publisher 子任务创建入口只计算一次机构，并统一标准化横屏和竖屏主标题。
- 将标准化后的竖屏标题同时传给竖屏背景、竖版封皮、播客封皮和 B 站封皮。
- 竖屏视频补跑会复用父任务已存在的三类独立封皮，避免重复浏览器渲染在视频合成前超时并拖垮整条任务。
- 竖屏下载 resolver 优先选择最新完成的完整补跑子任务，再回退父任务旧路径，防止新视频完成后详情页仍播放旧文件。
- 增加子任务参数契约测试，逐项断言五类视觉资产的主标题均带中文机构前缀。

## 验证

- 单元测试覆盖仅生成竖屏的方案二任务。
- 检查 publisher 子任务参数，确认所有视觉资产共享同一机构标题合同。
- 对历史任务重新生成封皮；旧视频须重新渲染，因为标题已经烤入视频帧。

## 复发预防

- 机构前缀属于上游内容合同，不允许由各模板自行猜测或拼接。
- 英文机构名、中文简称和旧通用前缀必须在同一别名表归一；连续的“机构：杰富瑞：”必须清洗为单一“杰富瑞：”。
- PDF 文件名明确机构时，旧结构化结果里的“机构研报”或错误简称不得覆盖它；`Bernstein / 伯恩斯坦 / 盛博` 统一输出“伯恩斯坦”。
- 新增视觉资产时必须纳入同一参数契约测试，不能只验证编辑器显示值。
