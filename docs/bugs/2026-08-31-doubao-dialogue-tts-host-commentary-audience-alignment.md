# Doubao 对话 TTS 主持人解读立场与后台话术泄漏

## 基本信息

- 状态：RESOLVED
- 严重级别：P2
- 影响模块：`doubao-dialogue-tts` 主持人写作、频道 profile、口播质量门禁
- 发现日期：2026-08-31
- 发现样本：洪总《市场将如何定价沃什和贝森特的巅峰对决》V2 审阅稿
- 当前处置：规则已进入结构化频道 Profile、Skill 正向写作契约和 dry-run 硬门禁

## 用户确认的栏目规则

1. 小君君在解读中提及作者时统一称“洪总”，不直呼“洪灏”。真实姓名可以保留在来源文件名、作者字段和非口播审校记录中。
2. 节目受众是洪总的长期听众与粉丝。小君君不是研报审稿人，不以挑刺、纠错或评判作者为主要姿态；核心任务是帮助听众听懂洪总在表达什么、论证如何展开、结论依赖哪些条件。
3. 编辑后台话术不得进入口播。已暴露的反例包括：“小君君先做一处事实核对”“名字这里应以美联储正式记录为准”“原文我们没有动”“判断时要把底稿校正”。这些句子对普通听众没有内容价值，还会破坏节目沉浸感。

## 根因

- 当前 Skill 虽然要求区分来源主张与主持人补充，也要求做外部核验，但没有进一步区分“幕后审校”与“面向粉丝的口播解读”。
- 在追求事实严谨时，编辑过程被直接写进主持人口播，导致小君君从认知向导滑向审稿人。
- 频道 profile 只记录了固定开场和宏观语言风格，没有记录作者称呼、受众关系和解释立场。

## 本期缓解

- 所有主持人口播中的作者称呼改为“洪总”；`final-script.md` 的可见标题和原文段落标题也同步使用“洪总”。
- 删除第 011 段的姓名纠错和“原文没动／底稿校正”表述，改为解释九比三分歧对政策门槛意味着什么。
- 将财政部回购与 QE 的工具差异改写为对洪总“政策对冲”逻辑的展开，不再使用“有道理”“分水岭”“拆掉误区”等隐含评审姿态。
- FOMC 姓名差异仍保留在 `review-notes.md`，不进入节目。

## 后续 Skill 升级要求

1. 为频道 profile 增加 `spoken_author_reference`、`audience_orientation` 和 `host_relationship_to_author`。
2. 明确两层输出：
   - 幕后审校层可以记录事实差异、来源、勘误和不确定性；
   - 口播层默认围绕理解增量写作，不展示编辑过程，不把非关键勘误做成主持人戏份。
3. 增加禁用口播模式检查，包括“原文没动”“按要求保留”“底稿校正”“我先纠正一下”“名字应以……为准”等编辑后台语言。
4. 增加作者称呼一致性检查：当频道 profile 指定“洪总”时，所有主持人口播不得出现“洪灏”；来源元数据和锁定原文不受影响。
5. 增加受众对齐审查：每段主持人解读应回答“这是否帮助洪总的粉丝更容易听懂原论证”，而不是“这是否展示了主持人比作者更严谨”。

## 验收标准

- 新研报主持人口播全程使用 profile 指定称呼。
- 主持人段落没有挑刺、审稿或居高临下的评判语气，但仍能补充必要机制与条件边界。
- 事实差异能够在非口播审校记录中追溯，且不会以制作说明形式泄漏到节目。
- 对 `final-script.md` 和 manifest 的主持人文本执行禁语扫描时，上述后台话术为零命中。
- 原文逐字保护、作者观点优先、声线配置和 dry-run 继续通过。

## 解决结果

- `xiaojunjun-honghao` Profile 已新增 `spoken_author_aliases`、`audience_orientation`、`host_relationship_to_author`、正向 `commentary_contract` 和 `forbidden_host_phrases`。
- 主持人口播中的“洪灏”会被 dry-run 拒绝并提示使用“洪总”；锁定原文和非口播元数据不受影响。
- “原文没动”“事实核对”“底稿校正”“按要求保留”等后台语言会在主持人口播层被确定性拦截。
- 同一纠错诱导场景复测后，口播只解释“重新评估”的机制和成立条件，事实核验移入非口播审校注。
- 清澈默认语速为 `1.08`，刘飞为 `1.00`；显式单期覆盖继续生效并在摘要中显示来源。
