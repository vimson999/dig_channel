# 评论索引清理迁移被混合所有者阻断

## 基本信息

- 状态：已修复并完成真实数据库迁移验收
- 严重级别：P1
- 影响模块：Alembic / PostgreSQL 索引维护 / 后端启动门禁
- 首次发现：2026-07-27
- 修复提交：当前工作区
- 根因分类：数据库对象所有权 / 在线 DDL 兼容性
- 复发键：`DB-SESSION-LIFECYCLE`
- 是否复发：同类数据库治理问题再次出现
- 关联记录：`2026-07-24-zsxq-comment-rewrite-stale-db-pool-index-sprawl.md`
- 防线层级：shared_guardrail / contract_test / observability

## 现象

执行 `flask db upgrade` 时，评论哈希与冗余索引清理迁移在删除
`ix_zsxq_topics_group_tab_type_create_desc` 时报错：
`must be owner of index`。后续 B 站充电快照迁移因此无法执行。

## 影响

- 新表、配置和草莓研报账号不能随版本正常落库。
- 后端运行时 schema 门禁会阻止依赖新表的功能启动。
- 已完成的应用代码无法进入真实采集与页面验收。

## 根因

历史索引由不同数据库角色创建，目标表和索引的所有者并不统一。迁移把
“索引存在”等同于“当前迁移角色可以删除”，直接执行
`DROP INDEX CONCURRENTLY`；但 PostgreSQL 删除索引要求当前角色拥有其所属表
或具备相应角色成员资格。项目已有维护脚本会检查所有权，Alembic 迁移未复用
这项成熟防线。

## 解决思路

结构兼容性变更与管理员清理分层处理：评论哈希列及回填必须成功；冗余索引若
当前角色有权则在线删除，无权则明确告警并跳过，不能让非阻塞的维护项卡住后续
业务迁移。

## 实际方案

- 删除每个冗余索引前，通过 `pg_has_role(table_owner, 'MEMBER')` 检查权限。
- 对无权限索引输出带索引名的 Alembic 告警并继续迁移。
- 运行时 schema 检查将关键表、列、权限和必要索引保持为硬错误；把遗留冗余
  索引归为管理员维护告警。
- 将下游迁移版本识别为评论清理迁移已经执行，避免成功升级后误报警。

## 验证

- 真实执行 `flask db upgrade`，成功升级至
  `20260727_bilibili_charging`。
- `scripts/dev/check-runtime-schema.py` 返回兼容，准确报告剩余 3 个
  `postgres` 所有者冗余索引。
- 新充电快照表完成 5 个账号的真实采集，后端 API 和首页看板均返回成功。
- 回归测试覆盖所有权预检、下游迁移识别和维护告警不阻断运行。

## 复发预防

- 所有清理历史数据库对象的迁移，必须同时判断“存在”与“当前角色有权操作”。
- 管理员维护项不得伪装成运行兼容性硬门禁；两者要分别输出并分别验收。
- 新迁移必须在真实应用数据库角色下执行，不能只依赖空库单元测试。

## 后续事项

- 由管理员删除剩余 3 个 `postgres` 所有者冗余索引；该维护项不影响本次功能。
