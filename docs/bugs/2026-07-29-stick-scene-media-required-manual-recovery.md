# 火柴人分镜图片与整篇 WAV 仍依赖手工续跑

- 状态：已修复、部署并完成指定真实任务验收
- 严重级别：P1
- 影响模块：火柴人视觉视频 / Gemini 分镜图片 / 整篇 WAV 时间轴对齐
- 首次发现：2026-07-29
- 修复提交：当前工作区
- 根因分类：编排自动化边界不完整、可恢复错误分类不完整
- 复发键：`ORCH-PARENT-CHILD-STATE`
- 是否复发：同类编排恢复问题再次出现
- 关联记录：`2026-07-22-terminal-polling-image-repair-payload-recurrence.md`、`2026-07-28-stick-audio-worker-state-hidden-by-web-cache.md`
- 防线层级：shared_guardrail / contract_test / runtime_acceptance

## 现象

火柴人任务会自动初始化并投递分镜图片，但 Gemini 页面暂时找不到生图工具、
输入框或生成结果时，部分错误不会进入已有的有限自动重试。来源研报已有完整 WAV
时，详情页能显示“复用整篇语音并对齐”，却仍要求用户点击按钮才会创建音轨和对齐任务。

指定任务 `ae12d525-fb5f-4344-a39d-67bfd5abf0d4` 的 38 张图片最终全部完成，
其中第 7 张第一次因“未找到 Gemini 工具/生成图片入口”失败；同时完整 WAV 已存在，
但音轨表没有记录，证明后台没有自动提交对齐。

## 影响

- 可恢复的浏览器页面波动会把自动工作流降级为人工逐图续跑。
- 已具备完整文案、分镜和 WAV 的任务仍停在“等待对齐”，无法直接进入成片预检。
- 页面存在操作按钮容易让实现方误以为后台链路已经自动化。

## 根因

图片任务已有最多两次 Celery 重试，但瞬时错误白名单只覆盖超时、页面关闭和网络错误，
没有覆盖 Gemini 页面入口、输入框、提交、结果定位和浮层污染等可恢复 UI 波动。

整篇 WAV 的绑定与对齐具备幂等后端函数，但仅由详情页 POST 操作调用；
分镜完成后的自动媒体编排只投递图片，没有复用同一能力。

## 解决思路

- 保留有限重试，不把提示词契约、视觉方案版本等确定性错误纳入盲目重试。
- 在分镜成功的后台编排节点调用已有的音轨绑定与对齐能力，不复制页面逻辑。
- 复用音轨和对齐任务的现有幂等判断，避免分镜重放造成重复任务。
- 没有完整 WAV 时正常降级为分段 TTS 能力，不把可选能力缺失误报为工作流失败。

## 实际方案

- 扩充图片瞬时错误分类；单图片仍最多自动重试两次，耗尽后保留人工续跑入口。
- 新增 `_auto_enqueue_whole_audio_alignment`，统一“查找完整 WAV、绑定音轨、幂等投递对齐”。
- `_dispatch_auto_scene_images` 完成父状态写入后自动调用上述能力，并记录音频投递结果或错误。
- 为指定真实任务补投整篇 WAV 对齐子任务 `c1468c66-4ccf-4901-9ac4-18009e4a2476`。

## 复发预防

1. 页面“续跑/复用”按钮只作为人工恢复入口；自动工作流必须从后台编排直接调用同一幂等服务。
2. 浏览器自动化错误必须区分可恢复 UI 波动和确定性业务契约错误，并设置有限重试上限。
3. 分镜完成的契约测试同时检查图片自动投递和完整 WAV 自动对齐，不再只验证图片。
4. 真实验收必须检查结构化音轨、对齐任务和分镜时间轴，不能只看页面是否显示按钮。
