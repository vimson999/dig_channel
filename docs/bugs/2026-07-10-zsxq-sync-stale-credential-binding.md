# 2026-07-10 知识星球同步绑定已删除凭据后无法自动切换

- 严重级别：P1

- 首次发现：2026-07-10
- 修复提交：待提交
- 根因分类：运行时凭据选择与持久化绑定生命周期不一致
- 复发键：`CREDENTIAL-SELECTION-LIFECYCLE`
- 是否复发：首次
- 关联记录：无
- 防线层级：shared_guardrail / contract_test / observability

## 现象

第 51 轮系统同步成功后，原同步凭据“前言0626”被删除，并新增了有效的“前言0710”。系统同步配置仍保存旧凭据 ID。第 52 轮在 preflight 阶段报“没有可用的平台凭据”，未创建 workflow，也未执行下载、清洗和发布。

通知同时把错误归类成 `invalid_group`，导致调度器停止；邮件却提示下一轮会继续预检，状态与实际行为不一致。

## 影响

- 新凭据已经存在且用途为 `zsxq.sync`，系统仍无法继续运行。
- 第 52 轮重复触发但始终未入队。
- 星球配置被误报为无效，增加了错误排查方向。
- 持续运行配置实际上停止，需要人工重启调度器。

## 根因

状态检查验证的是“是否存在任意 active 的 `zsxq.sync` 凭据”，真正执行时却按配置中保存的旧 `credential_id` 精确查询。旧凭据删除后，两次检查得到相反结论。

此外，`CredentialError` 继承自 `ValueError`，缺少凭据被通用 `ValueError` 分支归类为 `invalid_group`。调度器对 `invalid_group` 采取停止策略，因此通知文案与运行状态进一步分叉。

## 解决思路

配置中的凭据 ID 只作为“上次成功凭据的优先项”，不作为永久硬绑定。运行时按用途发现 active 候选，逐个验证其是否能访问目标星球；候选失效时继续尝试下一条。选择成功后回写新 ID，兼顾自动恢复和后续稳定优先选择。

缺少可用凭据必须使用独立错误类型和状态，不再借用 `invalid_group`。

## 实际方案

- 指定凭据已删除、停用或过期时，自动回退到 active 的 `zsxq.sync` 凭据。
- 对候选凭据执行目标星球访问校验；401、1005、非成员和权限错误会淘汰当前候选并继续轮换。
- 成功选择后，将新凭据 ID 和切换审计字段回写系统同步配置。
- 新增 `missing_credential` 预检结果，保持配置和调度器可继续运行。
- 新一轮成功入队后清理上一轮的 skip/error 标记。

## 复发预防

- 凭据配置必须按用途动态发现，持久化 ID 只能作为偏好，不能成为唯一入口。
- 预检状态和实际执行必须使用同一套凭据解析规则。
- 凭据、资源和外部平台错误必须分别分类，禁止通过共同父异常类型混入同一状态分支。
- 回归测试覆盖已删除 ID 自动回退、无目标星球权限时轮换、缺少凭据不误报星球无效。
