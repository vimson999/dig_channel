# 2026-07-02 研报视频关键帧渲染误用占位段落名

## 基本信息

- 状态：已修复
- 严重级别：P1
- 影响模块：report video / keyframe preview / preview clip renderer
- 首次发现：用户点击 9:16 关键帧大图时发现画面展示“节目段落 5”等占位内容
- 修复提交：待提交

## 现象

用户打开 `report-video` 关键帧预览文件时，竖屏画面使用了“节目段落 5”“节目段落 1/2/3”等占位字段，而不是口播脚本中的真实内容。旧预览 ID 为 `cf501630-a1cc-4b67-8b43-bf02d382c2e5`，`/files/4` 实际对应第 5 张关键帧。

## 影响

关键帧确认环节失去审核价值，用户无法判断最终视频内容是否跑偏。后续按单个里程碑生成样片时，也可能沿用相同的错误展示标签。

## 根因

竖屏关键帧模板优先读取 `segment.segment_title`、思维导图 `focus.label` 和子节点 label。部分任务的脚本段落和思维导图节点是通用占位值，例如“节目段落 5”或 `node_005`，渲染器没有识别这些低质量字段，也没有优先回退到 `voice_text` 中的真实口播内容。

## 解决思路

把“可展示内容”的选择逻辑收口到渲染服务内：先识别并过滤占位标题，再从结构化标题、摘要、口播文本和分析结论中提取可读标题与要点。模板只消费这层清洗后的展示值。

## 实际方案

- 新增占位 label 识别，过滤“节目段落 N”“章节 N”“program_N”“node_N”“当前段落”等值。
- 新增段落展示标题、节点展示标题、根主题展示标题和可视化要点提取函数。
- 竖屏、横屏、主题横屏、关键帧里程碑、样片里程碑统一使用清洗后的展示标题。
- 竖屏顶部主题 tag 和底部 chips 增加截断/换行保护，避免放大图出现横向裁切。
- 重启 dev stack，让 Flask 和 `report_video` Celery worker 使用新代码。
- 对同一任务重新生成 9:16 关键帧，新预览 ID：`e7e52f7d-0446-4320-9b5e-67e2d4e3aceb`。

- 使用原问题第 5 段真实数据渲染临时竖屏关键帧，确认标题和要点来自口播文本。
- 调用本机 API 重新入队任务 `6e315747-67fe-4330-8e30-874448bdfefc` 的 9:16 关键帧生成，Celery 任务 `c68b9fa1-c44d-4e74-9800-35e596be1c82` 完成。

## 复发预防

渲染层不得直接信任脚本段落标题或思维导图节点 label。进入画面的标题、标签和要点必须经过占位字段识别与真实文本兜底，尤其是关键帧、样片这类审核入口。

## 后续事项

旧预览文件不会被原地改写；页面需要使用新预览，或重新点击“生成关键帧”生成最新版本。
