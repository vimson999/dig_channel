# B站媒体分片上传耗尽有界重试

## 基本信息

- 日期：2026-10-24
- 状态：OPEN / REPEATED / OBSERVING
- 严重级别：P1
- 影响模块：Publisher upload-only、B站 SDK 分片上传、平台上传队列
- 根因分类：外部媒体传输连续失败，缺少可安全恢复的幂等续传合同
- 复发键：`BILIBILI-CHUNK-RETRY-EXHAUSTED`
- 是否复发：2026-08-06 日志与本轮均出现分片连续失败
- 防线层级：bounded_retry_active / durable_failure / idempotent_recovery_missing

## 现象与影响

固定窗 task `539c9f69-e522-405e-b45b-f470823ea57d` 在第 42/69 个媒体分片连续失败 4 次后终止，
durable 状态为 `failed/failed`，壁钟 253.799 秒。既有 `BoundedVideoUploader` 正确执行最大 4 次分片尝试和
总上传时限，没有无限占用队列；但用户仍需重新提交完整媒体，产生一次可见失败。

同一父任务/视频后续重新投稿成功，说明媒体内容与账号不是确定性拒绝；本窗 PgBouncer/SQL error、连接超时、
锁与长事务均为 0，失败位于 B站 SDK/网络分片传输边界。当前日志缺失败响应状态、目标/CDN 与网络阶段，不能
进一步臆断为单一 DNS、代理或上游故障。

## 根因与处置

已有有界重试是正确止损，盲目提高次数只会延长队列占用。真正闭环需要在失败现场持久化分片号、响应分类、
目标与已取得的上传会话标识，并证明 SDK 会话能否幂等续传；若无法证明，自动重投可能重复生成稿件，必须继续
人工重试。原始错误和任务失败必须保留。

本轮新增复发记录和门禁，没有改变重试预算或伪造成功。状态保持 **OPEN / REPEATED / OBSERVING**；下一次失败
必须补齐网络/上游分类。只有安全幂等恢复合同、定向测试、真实重试成功且后续完整窗口无重复稿件/无同码复发，
才可关闭。

重复稿件防线。0 次出现只记为未捕获，不能升级为已解决。

状态保持 **OPEN / REPEATED / OBSERVING**。下一次真实分片失败仍须保存分片号、响应分类、目标/CDN、上传
session 与各阶段耗时；只有证明可安全幂等恢复、真实恢复成功且完整后窗无重复稿件/同码复发，才可关闭。
